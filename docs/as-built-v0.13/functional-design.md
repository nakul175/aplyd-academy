# Aplyd Academy v0.13 functional design

This checkpoint extends the v0.12 working pilot. Existing learner, review, publication, membership, support and ecosystem commands retain their server authority. It adds no live AI service, partner connection, approved translation, accommodation or recognized credential.

## Content review and continuity

The existing owner operations panel derives content attention from the current permitted workspace projection and the current informational observation clock. It lists pending and approved drafts, elapsed or unknown publication review dates, retired publications and affected cohorts. Cohort matching uses the complete scope/program/version reference; a newer edition of the same program is never included by name alone. A cohort pause and a publication's enrollment closure remain separate facts.

The panel identifies an unavailable author or independent reviewer and offers reference-only navigation to the existing studio. It describes the action the current authority permits: a current author can recall/edit their draft; an orphaned draft may need archive and a separate copy; independent review or unchanged approved publication can remain possible after author loss. Owners do not gain another author's editing identity. Counts, waiting age and dates are observations, not service deadlines or automatic decisions. Current owner authority is required for this replacement panel; the existing facilitator view remains unchanged.

## Learner-controlled help details

Opening the ordinary help intake presents unchecked optional choices for the learner's requested language, declared assistance preference and an explicitly selected own course in the currently selected cohort. Course details resolve the exact accepted enrollment and cohort reference. Withdrawn, missing, foreign or unresolved references provide no course disclosure and no fallback.

An explicit preparation button appends only selected details to the current unsent description. It preserves title, category and cohort; it refuses overflow beyond the existing 2,000-character limit without truncating either the existing text or new details. Preferences are requests and declarations; the helper does not claim reviewed language content, available human assistance or approved accommodations. No private evidence, staff preference, score or contact information is added.

Preparing details and editing any field clear the audience acknowledgement. Consent is tied in memory to the exact account, workspace, request fields and current audience projection. A removed cohort leaves the draft visible and submission disabled until a current selection is made. Unsent fields are retained in account/workspace-scoped memory across navigation and authority remounts; browser close/reload persistence is not promised. Closing and reopening the dialog clears acknowledgement and optional disclosure choices. The final ordinary support-open command remains a separate explicit submission.

## Local ecosystem readiness

In the personal lab, each existing adapter offers a collapsed read-only inspection of the accepted local choice. It explains selected field scopes, purpose, exact pinned content, expiry, current informational readiness and separately preserved local receipt history. Unsaved form edits cannot replace the saved choice. Expired, withdrawn, paused, malformed, future or unavailable information cannot infer a live exchange or current summary. Independent withdrawal remains available where the existing server command permits it.

A generic partner-discussion brief is downloaded locally from constant definitions. It contains no account, profile, enrollment, grant, receipt or private learning values. Reference navigation opens the existing library and changes no learning. Health has no mapping; shared workspaces do not expose a personal mapping inspector. Server commands remain authoritative for grants, local tests and withdrawal. No partner receives information.

## Request behavior and private logs

Personal and shared unexpected errors now use fixed-category logs without exception text, partial request data or private database details. Existing JSON/media/origin checks, Request.text body reading, post-read size limits, identity, CAS, idempotency and audit behavior remain unchanged. Native malformed-input checks confirm recovery immediately after oversized uploads. No automatic retry is introduced.

The proposed streaming reader is deferred outside the product source. Three cleanup variants reproduced a local transport failure after an oversized request; the restored existing reader passed the exact same 32-case native suite. Its passing pure tests do not replace that failed native integration evidence. This release makes no new incremental-memory or transport-cancellation guarantee.
