# View loading · v0.8 as built

Academy loads staff, learning, networking and account screens when they are opened. Overview, the learning plan and support remain immediately available. The loading placeholder contains no saved learner or staff data. Components receive the current context after code arrives; an old permission projection is never stored in the loading module.

A failed module has a Back to Overview action and a deliberate Reload Academy confirmation. Cancel and navigation preserve in-memory unsent input. Confirmed reload discards unsent session text, with that consequence stated before confirmation; saved server work remains intact. The native framework retry was exercised and continued failing after a browser module error, so it is not presented as a successful recovery option.

Saved-data refresh starts focus on the main region before removing its retry button. It does not move focus again when a delayed response arrives. Operations destinations contain only references, remain scoped to the current workspace/view, and are reselected from current permitted data. Delayed destinations must not override a subsequent manual choice or move focus after the original focus window.

Client-size evidence describes emitted files and their parsed static import closure. Computed gzip is a local encoding calculation, not an observed network transfer or a loading-time result. Cold Overview browser inspection verifies that staff modules are deferred; no production latency, browser-cache performance or offline support claim is made.

## Validation boundaries

Executed local synthetic browser checks cover delayed staff/authoring/review/operations code, account and workspace changes, current role loss, personal drafts, a direct lesson URL, actual module failure and explicit reload recovery. Layout inspection covers phone/tablet and enlarged text. The v0.7 authorization/domain evidence remains historical; this release adds no API command, migration, live partner call or AI call. Exact executed results and source hashes are recorded in test-evidence.json.
