1. PRODUCT AND ACCESS BOUNDARY
The working pilot teaches farmers, MSME owners and public servants to check fictional sources, improve supplied AI drafts, handle information carefully and keep human authority explicit. Global discovery retains the three archived 0.1-review-draft pathways. v0.6 adds private workspace adaptation through a bounded content studio; it does not introduce a new global curriculum version.

A personal practice lab stores one authenticated account's private learning document. Its sample assessor/reviewer actors, discussions and ecosystem payloads are simulations. Creating or joining a shared workspace starts a separate document; it does not import lab evidence, sample decisions or posts. Shared learning uses real signed-in account IDs and explicit current staff assignments. A work-context selector changes examples/discovery, not permissions. [lib/academy-engine.ts:6–8,22; lib/academy-teams.ts:25,34,56]

Hosted site access, authenticated platform identity and Academy workspace membership are separate checks. The current repository describes owner-private hosting. An Academy invitation cannot alter that audience; access for a real participant must first be arranged through hosting controls. The app creates recipient-email-bound links for manual copying and sends no invitation email. Local synthetic identity headers test the application behind that boundary and do not prove real hosted sign-in or audience access. [README.md:22–24,40; app/chatgpt-auth.ts:21; app/api/teams/route.ts:9,14; lib/academy-teams.ts:36,50]

2. OWNER CONTENT STUDIO
Navigation: shared workspace → Workspaces & cohorts → Content studio. Current active admin membership is required to read the studio and use any content command. Author and content reviewer are relationships on a draft, not additional account roles. In particular, the learner-appeal role named reviewer does not grant content-review permission: content review requires another current workspace owner. All current owners can read workspace content drafts; ordinary learners cannot. [app/academy-teams-ui.tsx:23; app/academy-authoring.tsx:20–29; lib/academy-authoring.ts:25–26,138,145]

The studio edits ordinary fields: overview, three lessons, fictional source records, supplied AI drafts, nine quizzes, seven practical response prompts, four rubric criteria and their score anchors. It previews the document and issues. There is no embedded AI generator, arbitrary content schema, file upload or accredited credential authoring. Adult audience, English, ecosystem/role/level, nested IDs, classification/claims, follow-up structure and the existing critical-gate positions remain fixed. [app/academy-authoring.tsx:17,31; lib/academy-authoring.ts:7–11,43–108,157]

Exact command set — all eight commands use the trusted signed-in actor and server time:
• content-copy {sourceRef}: any current owner copies an exact global seed or own-workspace publication. A global copy gets a new private program ID; copying a private publication keeps its program ID and starts a new draft. No source version is changed. Retired private publications can still be copied as a source for a reviewed replacement. [lib/academy-authoring.ts:124–129]
• content-save {draftId, revision, document}: original author, still a current owner, saves only state draft. Shape, locked-field and size failures reject the save. Incomplete required text and semantic issues may be saved for later correction. Each save advances documentRevision and draft revision and clears approval. [131–134]
• content-submit {draftId, revision, reviewerId, reviewDueAt}: original author submits a complete draft to another active owner. Review date must be exact UTC ISO, future and within 730 days. State becomes in_review. [136–139]
• content-recall {draftId, revision, reason}: original author recalls in_review or approved content to draft; approval is cleared. Reason is 10–1,000 characters. [141–142]
• content-review {draftId, revision, decision, note, checks?}: assigned independent current owner reviews in_review. decision=changes returns to draft. decision=approve requires a 30–2,000-character note and all five checks true: sources, answers, rubric, safety, accessibility. Approval binds the document revision and canonical SHA256. [144–149]
• content-publish {draftId, revision}: any current owner publishes approved content only while its independent reviewer is still an active owner, the review date is future, validation passes and the document hash/revision still match approval. Creates one immutable private publication, then marks the draft published. [151–158]
• content-archive {draftId, revision, reason}: any current owner archives any unpublished active state: draft, in_review or approved. Reason is 10–1,000 characters. Terminal archived state keeps the exact saved document, approval and history, frees one active slot and continues counting against retained draft capacity. It cannot be edited, reopened or published. [160–161]
• content-retire {publicationId, reason}: any current owner closes an available publication to new offerings and enrollment. Reason is 10–1,000 characters. Only availability/provenance change; snapshot and hash remain unchanged. Retirement does not pause existing learning. [163–164]

State flow:
copy → draft → submit → in_review → approve → approved → publish → published
in_review → changes → draft; in_review/approved → recall → draft
draft/in_review/approved → archive → archived
publication available → retire → retired
No terminal reopening or publication mutation command exists. [lib/academy-authoring.ts:119–169]

3. VALIDATION AND PEDAGOGY
There are exactly three lessons, three questions per lesson, four distinct trimmed options per question, seven practical prompts and four rubric criteria. Criterion weights are positive integers totaling 100; the original three critical gates and five anchors (0–4) stay in place. Whole pathway time must cover all lesson estimates; minutes are whole numbers 5–720. The document must fit 65,536 UTF-8 JSON bytes. [lib/academy-authoring.ts:61–108]

Source packets contain 1–20 plain records, each with a sourceId and bounded primitive facts. IDs are compared after trimming. A later teaching duplicate is valid only when duplicateOf exactly names the earlier same source ID and sourceNote explains it with at least ten trimmed characters. Unmarked duplicates, a marker on the first occurrence and metadata-only/blank facts fail complete validation. The farmer seed intentionally contains a copied transport line; its private template annotates that duplication and preserves the contradictory figures, teaching note and answer references. Global archive bytes remain unchanged. Legacy string rows become referenced objects only in a private copy. [lib/academy-authoring.ts:32,47–58,91; lib/curriculum-versions/0.1-review-draft.json]

Preview is advisory on the client; submit, approval and publication revalidate the server-held document. Text/schema validation cannot establish sector accuracy or professional fitness. Independent human content checks remain necessary. [lib/academy-authoring.ts:116,137,148,154,172]

4. VERSIONED OFFERINGS, LEARNING AND RECORDS
A publication key contains scope + programId + versionId. Private scope is the exact workspace ID. New cohort creation can choose an exact available private publication while its review date is future. A cohort's reference is then fixed; there is no retarget command. New enrollment pins that cohort reference. Later copies, new publications, catalog changes and retirement cannot move existing enrollments or assessments to another version. Unknown, missing or conflicting saved references fail closed; no current-rubric fallback is permitted. [lib/academy-curriculum.ts:47–118,143–156; lib/academy-teams.ts:53,59]

Private course discovery is assembled only from the current authorized workspace's visible cohorts and the learner's continuing enrollments. Learners with an active learner role can see workspace offerings, including their referenced private versions; staff visibility follows current cohort scope. Other workspaces and the global catalog never receive private drafts or publications. Removed members retain the versions needed for their own saved history. [lib/academy-teams.ts:70,77–78; app/academy.tsx:31–34]

Closing a publication or reaching reviewDueAt blocks new cohorts and new enrollments, but preserves existing version resolution and continuing work. Pause an affected cohort separately for an immediate learning/review stop. Existing same-cohort enrollment is recognized before the new-enrollment availability check. [lib/academy-authoring.ts:173; lib/academy-teams.ts:54,56,59–60,80]

The fixed pilot assessment requires completion of all lessons, seven practical responses of 30–10,000 characters, at most three attempts, a weighted score of at least 70 and every critical gate satisfied. Independent assigned account reviews are required in shared workspaces; the original assessor cannot decide the appeal. Appeals open within 14 days and preserve the original decision. Records are private nonaccredited practice records, with saved title/version/claim and reviewer provenance; they do not confer professional authority, public verification or issuer recognition. Per-program configurable pass policies remain outside this studio. [lib/academy-engine.ts:20–22,27–34,49; lib/academy-authoring.ts:157; lib/academy-teams.ts:33,55–56]

5. SUPPORT: SIX ACTIONS WITH CURRENT PERMISSIONS
Categories: access, learning, technical, content, accessibility, privacy. Any active member can open a request and read their own threads. Active owners see queue metadata across the workspace. A facilitator sees learning/content queue metadata only for a current cohort in their scope. Queue visibility alone never grants message-body access; an eligible handler independent of the requester must explicitly claim the case. Owner requesters cannot handle their own case. Assessor/reviewer/moderator roles alone do not grant support handling. [lib/academy-support.ts:5,18–29,71–75]

• support-open {category, cohortId, subject, body, audienceAcknowledged}: acknowledgement must be true; title 5–160, body 10–2,000 characters. cohortId may be null for workspace access. Owners and active learners may choose an existing cohort even before enrollment; other staff need current scope. Creates open, unassigned thread. [44–48]
• support-claim {requestId}: eligible independent handler claims an open case with no current eligible handler. Concurrent claims compete on workspace revision. [50–52]
• support-reply {requestId, body}: open case; requester or its currently assigned eligible handler; body 10–2,000. [54–55]
• support-resolve {requestId, resolution}: current handler only; resolution 20–2,000; appends immutable resolution history and marks resolved. [57–58]
• support-reopen {requestId, body}: original active requester only, resolved → open; reason 10–2,000. Clears the current resolution pointer while retaining prior resolutions; an eligible assignment may remain. [60–61]
• support-withdraw {requestId}: original active requester only, open → withdrawn. Terminal read-only history remains; withdrawal is not erasure. [63–64]

All protected workspace mutations reconcile assignments. Loss of active owner status or facilitator cohort/category eligibility clears the handler assignment; restoring permission requires a fresh explicit claim. Inactive members can read their own past requests but cannot reply, reopen or withdraw. Current read projections remove unauthorized bodies immediately. [lib/academy-support.ts:20–26,71–75; lib/academy-teams.ts:38]

Support is in-app only. Check back for replies; there is no email notification, staffed response promise, emergency channel, formal accommodation decision, grade change or erasure service implied by this workflow. [app/academy-support.tsx; app/academy-teams-ui.tsx:33]

6. RETENTION, CAPACITY AND UNSENT INPUT
Workspace caps: 24 retained draft records, four active drafts, eight retained immutable publications, 650,000 UTF-8 JSON bytes for authoring plus reserved final closures; one content document at most 65,536 bytes. Published/archived drafts free active slots but remain in the 24 total. Retired publications remain in the eight total; no deletion or quota-reset workflow exists. Draft ordinary history is at most 100 events; archive can append the reserved final event 101. [lib/academy-authoring.ts:8,20,115,125–126,155,167–190]

Support caps: 100 retained requests, five open per requester, 20 messages per thread including initial/reopen messages, 20 retained resolutions, 100 ordinary lifecycle events. Withdrawal may add event 101 at a full history. Support bodies plus reserved withdrawal events fit 250,000 UTF-8 JSON bytes. [lib/academy-support.ts:13,30–31,47,58,67,81–87]

The workspace aggregate has a 1,200,000-byte ordinary ceiling and 1,800,000-byte protective ceiling. Dynamic reserved capacity accounts for all pending content archive/retirement and open-request withdrawals, including worst JSON escaping and admitted identity lengths. These are pilot admission checks, not evidence of tested production load or a blanket guarantee for externally corrupted/oversized legacy rows. [lib/academy-storage.ts:5–25]

An author's own unsent document and review inputs survive component unmount/permission refresh in workspace-keyed session memory. They are not saved to the database or local storage, and a page reload can lose them. Conflicts retain editor text, show the current saved version and require an explicit reload/discard or acknowledged rebase; no silent overwrite occurs. Archived/published views show canonical saved content and label any own retained unsent text separately. Loss of owner authority hides former server documents. [app/academy-context.tsx:6–18; app/academy-authoring.tsx:24–28,41–63; app/academy.tsx:29]
