Browser React/Next views call same-origin /api/academy for the personal account document and /api/teams for shared aggregates. Route handlers obtain platform identity through getChatGPTUser(), use Cloudflare env.DB, run domain transitions, and commit state/audit together in D1. Identity headers are supplied by the hosting/auth boundary; accepting synthetic local headers during tests does not make arbitrary external headers trusted in production. Hosting audience control is external to Academy membership. [app/chatgpt-auth.ts:21; app/api/academy/route.ts:6,9–11; app/api/teams/route.ts:9,15–24]

Current implementation stores JSON aggregates in SQLite/D1, not the earlier reference PostgreSQL schema. Six declared tables: academy_workspaces, academy_audit, academy_teams, academy_team_audit, academy_invite_tokens, academy_team_history. Content drafts/publications and support threads are nested in academy_teams.data. No separate CMS database, arbitrary upload store or outbox is introduced by v0.6. 2. SHARED API CONTRACT
GET /api/teams: directory metadata for the signed-in member's workspaces plus own account name/email.
GET /api/teams?id=<workspace>: current authorized projection + workspace revision.
GET /api/teams?invite=<token>: recipient-bound invitation metadata; no workspace bodies/token hash.
POST /api/teams: {teamId, revision, actionId, command}; exact outer keys, integer revision, actionId matching [a-z0-9-]{20,80} case-insensitively. Content and support payload fields are in the FSD delta. No client author, reviewer identity, role, scope entitlement or timestamp overrides the server actor and time. [app/api/teams/route.ts:14–18]

JSON content type is required. If an Origin header exists it must match request origin. The raw request limit is 100,000 JavaScript string units, distinct from UTF-8 document/storage limits. Responses are no-store, nosniff and no-referrer. Success returns current state, team projection, top-level contentVersions and revision; a replay adds replayed:true. Errors are {error:string}, not the proposed /api/v1 correlation/field-error format. Relevant status families: 400 invalid/extra fields; 401 no identity; 403 current authority; 404 absent/out-of-scope; 409 stale/conflicting state or action-ID reuse; 413 capacity; 415 non-JSON; 422 semantic validation; 503 unavailable/unexpected failure. [app/api/teams/route.ts:7–9,16,19,23]

The route reads the current aggregate and validates current active membership before an ordinary action replay. A durable key (team_id, actor, event_id) stores SHA256(JSON.stringify(original command)). Identical replay returns the CURRENT authorized projection and revision without a new mutation; changed command body with the same key returns 409. Key order changes can change this request hash. Content approval uses a different canonical document hash. Role-specific transition checks run for new commands, not again merely to return an already-completed action replay; current projection still filters lost authority. [app/api/teams/route.ts:17–19; db/schema.ts:5]

New mutations require the expected workspace revision. applyTeamCommand() remains synchronous for legacy branches and returns a Promise for content commands; the API always awaits it. The content branch clones first, awaits SHA256, then returns a candidate aggregate. UPDATE uses WHERE id=? AND revision=?; a losing compare-and-swap returns 409. It cannot partially finalize a publication or assessment against an intervening permission change. State update, optional invitation-hash index, optional history packet and audit insert form one D1 batch; each insert depends on changes()=1. Unique token failures roll back the batch; a failed commit does not append an orphan audit/history record. [lib/academy-teams.ts:39–44; lib/academy-authoring.ts:118–122; app/api/teams/route.ts:20–23]

3. EXACT CURRICULUM RESOLUTION
ContentRef is {scope, programId, versionId}; exact keys, validated bounded identifiers. Registry keys are JSON tuples, not delimiter-concatenated strings. Registry construction rejects duplicate keys and program identity mismatch; it clones and recursively freezes snapshots. Global 0.1-review-draft remains archived separately, with expected SHA256 9fc83c8dd615456db8f49d140f56bff566e05c14d32ebb70a14cdcb73078b7e4. [lib/academy-curriculum.ts:4–26,47–118,121–131]

pinnedRef(record) uses an explicit contentRef if present and rejects disagreeing legacy programId/version. Without contentRef, BOTH programId and version must be explicit; only that legacy global reference is accepted. Unknown version returns 409; forbidden scope returns 404. Historical lesson, evidence, assessment, review and title/rubric rendering resolve the WHOLE saved record and never substitute current discovery content. [lib/academy-curriculum.ts:68–82,103–112,143–156; lib/academy-engine.ts:12–15,22]

ContentContext={registry, allowedScopes}. The trusted shared dispatcher lazily creates {registry:workspaceRegistry(team), allowedScopes:['global',team.id]}. This is passed as the sixth applyCommand argument and as the third planOptions argument. Scopes come from the authenticated selected workspace, never from requested ref.scope. workspaceRegistry includes preserved global snapshots and that workspace's immutable publications, including retired versions for historical resolution. It does not mutate a process-global registry. [lib/academy-curriculum.ts:143; lib/academy-teams.ts:44,46,56,59–60; lib/academy-authoring.ts:30–31]

For new cohort/new enrollment, requireAvailablePublication additionally checks private availability and a future reviewDueAt using trusted current time. Cohort creation stores exact ref/version. Enrollment stores exact ref/version/cohort and fixed draft/nonaccredited claimPolicy. Existing same-cohort enrollment short-circuits new availability checks after exact pin resolution. Publication retirement changes metadata only; review-date expiry is evaluated, not stored as a terminal content state. [lib/academy-authoring.ts:173; lib/academy-teams.ts:53,59,80]

4. AUTHORING TRANSACTION AND REVIEW BINDING
applyWorkspaceContentCommand() rejects unknown/extra fields, requires current owner authority, clones the aggregate, performs its lifecycle check, validates document content, checks byte budget and returns only on success. findDraft() requires exact draft revision inside the already-fenced workspace revision. Save increments documentRevision and draft revision; other lifecycle events increment draft revision. Archive/retire provenance lives in retained draft history/publication metadata plus durable API audit; these protective closures do not add a duplicate activity event. [lib/academy-authoring.ts:23–29,112–169; lib/academy-teams.ts:43]

Canonical document hash recursively sorts object keys while preserving array order, then uses SHA256. Approval saves author-independent reviewer identity/name, documentRevision, documentHash, reviewedAt, note and five exact true checks. Publish revalidates document completeness/date/current reviewer authority and recomputes the hash before storing a detached snapshot with fixed policy. Published content and its hash have no edit command. A replacement starts by copying a preserved publication into another private draft; a later publication receives another cp-UUID version key under the same program ID. [lib/academy-authoring.ts:35–40,138–158]

Private template conversion is narrow: assign private program ID; force fixed classification/claim/exclusions/fictional notice; floor total minutes to lesson sum; wrap legacy string source rows; annotate the known copied farmer line only in the private template. The global JSON archive is never rewritten. Duplicate-source, meaningful-fact, trimmed-option and time consistency checks are server validation, not a source-fact truth oracle. [lib/academy-authoring.ts:32,43–108]

5. READ PROJECTIONS AND CLIENT RESOLUTION
projectTeam() first establishes membership, then projects own learner state, permitted cohorts, thin progress summaries and explicitly assigned pending evidence. An owner does not automatically receive learners' draft/practical fields or decisions. Assigned staff need current independent role plus cohort scope and current explicit assignment. [lib/academy-teams.ts:19,33,68–76]

neededRefs is built INTERNALLY from own enrollments, visible cohorts and assigned-review enrollment references; malformed pins are ignored for content projection and later fail closed in the reader. projectWorkspaceContent() returns all private snapshots/full drafts/publication management metadata only to active owners. Other members receive only snapshots keyed by neededRefs, no drafts or owner review notes. Removed members get their own historical state/necessary versions, no owner studio or support queue. [lib/academy-teams.ts:70,74,77–78; lib/academy-authoring.ts:175–180]

The browser creates a memoized detached registry from global seed snapshots and the CURRENT workspace's server-filtered contentVersions; allowed scopes follow activeWorkspace. Workspace changes clear private versions, and refresh/load sequencing rejects stale workspace responses. Private discovery uses authorized cohorts/continuing enrollments; historical cards/reviewers use exact pins. Error refreshes sanitize protected projections. This limits scope leakage; it does not revoke content already read or personally copied outside the application. [app/academy.tsx:18–34,43]

Owner document scratch is in an AcademyContext in-memory map keyed by workspace + field key. useWorkspaceDraft() survives conditional-tab unmount without database/local-storage persistence. DraftEditor saves against its captured base revision, retains unsent text on conflict, and accepts returned revisions after clean saves. Explicit reload/rebase avoids silent stale replacement. Terminal views use canonical saved content, while separately labelled own unsent text remains in memory. Reviewer preview uses the current server document, with scratch only for the reviewer's own inputs. [app/academy-context.tsx:6–18; app/academy-authoring.tsx:24–28,41–63]

6. SUPPORT PROJECTION AND CURRENT ASSIGNMENTS
The six support transitions run within the same workspace revision as all other protected mutations. Only the support slice is cloned and committed after all checks; failure leaves the supplied document unchanged. Requester/handler/time are server-bound. Effective handler eligibility is active independent admin, or active facilitator for learning/content in an existing scoped cohort. finishAccess() reconciles support/network after every protected mutation; invalid support assignment becomes null and a restored role must claim again. [lib/academy-support.ts:20–26,39–68; lib/academy-teams.ts:38,48,63]

projectSupport() returns mine, queue and assigned. mine contains the requester's full retained history even if inactive. queue is metadata only, including canClaim and whether an independent eligible handler exists. assigned contains full threads only while the account remains the effective eligible handler. Full thread projections strip internal requester/handler and message/resolution/event actor IDs, retaining display-name provenance. This is separate from content-authoring ownership and assessment assignment. [lib/academy-support.ts:71–75]

7. ADMISSION BUDGETS AND TERMINAL CLOSURES
All bytes are UTF-8 size of JSON.stringify(value). Authoring: document <=65,536; authoring JSON plus dynamic closure reserve <=650,000 when growing. Support: support array JSON plus open-case withdrawal reserve <=250,000. Workspace ordinary growth <=1,200,000; protective growth <=1,800,000. Total aggregate bytes plus support and authoring reserve must remain <=1,800,000 when growing. Non-growing operations are allowed; this is not an unconditional repair policy for externally oversized/corrupt data. [lib/academy-authoring.ts:8,81,167–190; lib/academy-support.ts:67,81–87; lib/academy-storage.ts:5–25]

authoringClosureReserve() sums worst-case growth of one archive for each active draft plus retirement metadata for each available publication. It uses the largest saved actor ID from current admitted members, 80-unit display names, 1,000-unit reasons, a 24-character ISO time and worst JSON escaping. supportClosureReserve() reserves each open requester's final withdrawal event, preserving bodies/history. Membership admission and every transition recompute both reserves. Ordinary 100-event caps reserve one final archive/withdraw event at 101. These reserves protect terminal closure capacity without deleting evidence. [lib/academy-authoring.ts:115,183–190; lib/academy-support.ts:31,78–87; lib/academy-storage.ts:22–25]

Protective mutations include archive/retire, support withdrawal, invite revocation, cohort pause/close, moderation hiding, directory opt-out, RSVP removal, session cancellation and membership removal or subset-only authority reduction. Grants and ordinary content additions remain on the ordinary ceiling. Protective classification is not permission bypass: normal current-role/lifecycle rules still run. [lib/academy-storage.ts:8–18]

separateHistory() keeps the newest 200 activity and 200 moderation records in the hot aggregate; older records become an atomically committed academy_team_history packet. Learner evidence, assessment decisions, content lifecycle and support history are not removed by this helper. History reads still require current owner/moderator authority; this is not a general retention/erasure schedule. [lib/academy-storage.ts:28–31; app/api/teams/history/route.ts; app/api/teams/route.ts:20–23]
