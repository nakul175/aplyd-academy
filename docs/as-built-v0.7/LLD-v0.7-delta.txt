APLYD ACADEMY — LOW-LEVEL DELTA v0.7
Status: source-grounded local read model and client state contracts; no new migration.

L07-01. Boundary
GET /api/teams?id=<workspace> still returns projectTeam(team, current authenticated actor), revision, own state and authorized contentVersions. deriveWorkspaceOperations accepts only this already-filtered team projection plus an exact UTC ISO observation time. Feeding a raw stored Team or another actor's projection violates its contract. It is a pure read model, not an authorization layer. Commands use existing server context, current roles/scopes/assignments, revision fence and action hash. GET/POST personal /api/academy responses now include currentUserId so client account isolation can use the trusted actor.
Sources: app/api/teams/route.ts; app/api/academy/route.ts; lib/academy-teams.ts projectTeam; lib/academy-operations.ts.

L07-02. Canonical enrollment metadata
projectTeam adds practiceRecordStatus=e.record?.status??null, hasOpenAppeal=!e.withdrawn&&e.appeals.some(status==='open'), hasPendingAssessment=!e.withdrawn&&e.attempts.some(!decision). The old status field is preserved. Existing owner/facilitator summary filtering is unchanged. These fields include no evidence, score, appeal reason, rubric or new durable state. They are calculated from the authoritative stored learner enrollment.
The read model prefers explicit practiceRecordStatus and boolean flags; legacy status fallback remains for older projection fixtures without fields. Suspended count requires explicit suspended status. The presence of an open appeal does not infer suspension. Summaries are grouped only into cohorts whose canonical canHost===true.
Sources: lib/academy-teams.ts projectTeam summaries; lib/academy-operations.ts summary accumulation.

L07-03. Bounded derivation and ordering
OPERATIONS_LIMITS: cohorts20; summaries5000; pending5000; assigned5000; support100; sessions100; drafts24; publications8; visible rows8. Owner member and eligible host roster arrays are capped at100. Missing optional lists are empty; malformed/oversized required lists or invalid observation time produce null instead of partial totals. Item IDs remain bounded to160 characters. Admitted assignment subject strings are handled separately, with a 1,800,000-character outer bound; current names stay bounded80. Name/title truncation affects display only and cannot rewrite assignment authority.
Review/support rows sort by recorded oldest date with ID tie-breaker; invalid/future age is null, not invented. Content prioritizes due/unknown-date/in-review/approved/soon; sessions sort by start then ID. Totals use full bounded visible inputs and lists show first8. Saved lessons sum validated nonnegative integer completedLessons. Scope excludes broader boardAccess or learner-visible cohorts.
Source: lib/academy-operations.ts types, helpers, deriveWorkspaceOperations.

L07-04. Output minimization
WorkspaceOperations is transient and contains bounded metadata. Review rows contain learner display name/cohort/type/date/current assignment and destination reference, without evidence or scores. Support rows contain category/date/cohort/current handler bits, without subject/requester/body/replies/resolution. Owner content rows contain title/state/reviewer/date bits, without source packet/hash/rubric/notes. Session rows contain dates/place counts/current host/attendance-count bits, without instructions/participant names/registration IDs. The source API may legitimately include the current actor's assigned bodies; the operational model deliberately does not copy them.
Source: lib/academy-operations.ts and app/academy-operations.tsx.

L07-05. Navigation lifecycle
OperationsDestination={view:'teams'|'studio'|'support'|'network', section?:known section, id?:item ID}. openOperation stamps workspaceId and calls go(view). useOperationsNavigation verifies workspace/view equality, calls the latest destination handler, and clears only that exact target object. A false return retains the target for the child content view. Consumers select existing current assigned IDs/current draft IDs; otherwise they open a safe unselected list. focusOperationItem finds matching attribute values with equality rather than interpolating IDs into selectors; a double animation frame begins a bounded one-second lookup for a visible enabled current control, canceled on hidden page, expiry, latest-request replacement, manual focus movement, workspace/account/authority/view scope change or hash change. No operation body or authority token is carried or written into URL/hash.
Sources: app/academy-context.tsx; app/academy.tsx provider/selectWorkspace; app/academy-teams-ui.tsx; app/academy-authoring.tsx; app/academy-support.tsx; app/academy-network.tsx.

L07-06. Read/write response fencing
Academy stores loadSequence and writeInFlight refs. load refuses an ordinary refresh during a write; each load gets an increasing sequence. Only the latest sequence applies results/errors/loading completion. Writes invalidate earlier reads before POST and after success; conflict/access handling can call load(true). directory(sequence,expectedAccount) also checks sequence before applying a list, and detects actor mismatch against the response being accepted. The operation page's own pending ref suppresses duplicate read refreshes. Context saving reflects actual writes, while busy also covers inactive membership; read-only history can still refresh.
GET 401/403/404 invokes maskReadAccess: fresh personal state/revision, empty private versions/targets, inactive access-unavailable shared projection, cleared workspace directory, incremented authorityEpoch. Fragment key forces destination components to discard retained server-derived state. Account changes clear scratch/targets and increment epoch; scratch is keyed by an unambiguous JSON tuple of account, workspace and form key, in memory only. This documents the code path, not a hosted identity-switch guarantee. Root race/denial browser tests must be linked before declaring release verification.
Sources: app/academy.tsx maskReadAccess, acceptAccount, directory, load, cmd/teamCmd, provider, Fragment; app/academy-context.tsx useWorkspaceDraft.

L07-07. Refresh observation time
OperationsView records a client ISO asOf at mount. Manual or visible 30-second refresh awaits load(); only true success updates asOf. Visibility return triggers the latest refresh callback. Invalid persisted timestamps show checking/unavailable messages. Age is floor((client observation time-recorded time)/day) only for valid dates not in the future. Publication due/seven-day/session observations therefore depend on device time. Authoritative intake/attendance decisions remain existing server checks; there is no staff turnaround timer or response SLA.
Source: app/academy-operations-page.tsx; lib/academy-operations.ts iso/age and date windows.

L07-08. Persistence and provenance
No v0.7 D1 table or migration is added for operational data. Existing Team learner record/attempt/appeal objects remain canonical. A timely appeal does not rewrite the original assessment decision, issue time or content pin. An adverse appeal appends its independent decision and suspends the current record; a passing retry obtains its own assessor provenance while older attempts/appeals persist. Retired/due private publication availability does not alter exact historical content references. No projection field is a durable qualification or partner exchange receipt.
Sources: lib/academy-engine.ts assessment/appeal/record transitions; lib/academy-authoring.ts and lib/academy-curriculum.ts exact resolution; lib/academy-teams.ts current read projection; v0.6 dictionary.
