Aplyd Academy data dictionary

Version 0.1 · 5 October 2026 · Proposed R1 implementation model.

The CSV dictionary is the canonical per-column reference for schema.sql. Every defined table column appears exactly once. It records SQL type, nullability, keys, checks, default, data classification, accountable owner, purpose, release and retention category. This readable companion explains entities, data handling and constraints requiring domain enforcement.

Conventions

UUID values are generated by the service. Timestamps use UTC timestamptz; local time is a display preference. SQL numeric is represented as a JSON number with agreed precision. JSON payloads require validation against typed domain schemas before storage. Array fields have size and value limits at the API/service boundary. Null means absent or not applicable, not an empty string. Account identity is global; tenant is the delivery security boundary; ecosystem is context. Unique optional keys permit multiple NULLs. Text email is not a global identity key. issuer + subject establishes identity linkage after token validation and explicit collision handling.

A row's lifecycle and field values do not alone grant access. Composite FKs prevent cross-tenant association; scoped authorization prevents reads and mutations. Optional composite links are validated before persistence even when SQL MATCH SIMPLE permits null components. External references and raw personal data must not appear in log metadata or idempotency keys.

Retention categories

Durations and residency are unresolved business decisions. These categories are lifecycle triggers for a retention schedule, not approved legal periods. Before launch, each must have an owner-approved duration, deletion/anonymization method, hold behavior, backup treatment and evidence of purge. A withdrawn optional consent affects future sharing immediately and does not automatically erase an earned credential or mandatory audit evidence.

Cross-row and lifecycle constraints

  1. Publishing requires a reviewer, valid content links, covered competency dimensions and an approved completion/attempt policy. Published versions and activities are immutable; update by creating a new version. SQL records publication facts; service verifies the full policy.
  2. Offering opens only against published versions; enrollment requires an active tenant membership, permitted offering and available cohort capacity. Program and assessment references must be consistent. Transactional cohort locking prevents oversubscription.
  3. Every attempt's assessment must belong to the enrolled program and published policy. One nonterminal attempt per enrollment and assessment is enforced by a partial unique index. Attempt counts and retry windows are transactionally checked.
  4. Decision criterion scores must cover each published criterion exactly once; score may not exceed criterion maximum. Pass requires normalized score >= published pass_score AND every critical criterion passing. SQL cannot express the cross-row total; the decision service recomputes it.
  5. Assigned assessor permissions and learner independence are checked for every review. Appeals require an independent reviewer and append a superseding decision within the same attempt. A decision cannot form a supersession cycle.
  6. Credential eligibility_decision_id must belong to the credential enrollment, be currently effective and pass the relevant standard. Completion/participation have their own documented evidence. The FK alone does not establish that provenance.
  7. Credential correction may change approved display fields via an append-only event and current projection. It cannot silently change standard or earned evidence. A new qualification uses a new standard and separate award key.
  8. Consent resource_id is polymorphic. The privacy service validates owned resource, tenant, recipient, purpose and field allowlist. Delivery rechecks active partner consent, client, membership, destination and current credential status. Public verification sharing is a separate learner toggle: a private credential may be disclosed to an authorized partner, and disabling its public URL does not revoke an independent partner grant.
  9. Community/cohort membership, staff scopes, post visibility and moderation authority are cross-row authorization checks. Post replies remain within the same community by FK.
  10. Audit, score, decision and credential-event records are append-only by application role permissions. Published content receives mutation guards. No broad cascade delete is allowed; governed purge jobs honor retention holds and remove dependent rows in an approved order.

Validation status

Generation checks verify every schema column has exactly one CSV entry, all foreign-key targets exist, referenced columns are unique, and constraint identifier names are bounded. JSON and CSV are parsed locally. PostgreSQL is unavailable in this environment: no migration, query plan, RLS or transactional behavior has been executed. Apply this reference to disposable PostgreSQL before implementation approval and test publication guards, scoped roles, data purge ordering and races.
