Status: frozen candidate documentation; root integration/hosted verification pending.

Existing API and persistence
Use the existing POST /api/academy envelope {revision,actionId,command}. Authentication chooses academy_workspaces.owner from the current account. No caller owner or learner selector is added. Existing origin/content checks, action hash/replay, revision compare-and-swap, durable batch and audit logic are unchanged. The domain function remains synchronous. No D1 schema migration is needed; new Workspace fields are optional and absent in legacy/fresh rows until explicit use. Shared Team command dispatch has no new branch and rejects these actions.

Command contract
- ecosystem-grant: exactly type,partner,enrollmentId,scopes,durationDays. Valid partner agri|msme|public; nonempty unique scopes learning.progress|practice.record; numeric durationDays1|7|30. Own active/unpaused enrollment, exact partner pathway, exact global immutable ref/version and unique valid lesson IDs are required. UUIDs and timestamps are server generated. No requested version/ref, actor, payload, subject, account, URL or expiry can enter the command. New choice is prepended, prior null same-partner choices closed once, and history retained. Cap24.
- ecosystem-withdraw: exactly type,grantId. Find the own retained choice; validate its saved shape; store canonical server UTC once. Future creation/existing withdrawal refuses409. A legitimate past withdrawal is idempotent in its timestamp. It does not resolve curriculum or interpret receipt authority. Existing API action replay controls transaction idempotency.
- ecosystem-test: exactly type,grantId. Strict-read choices and receipt history; require one current active choice per partner; re-resolve exact global pin with allowed scope['global']; validate current exact lesson IDs; build a minimal schema-validated payload from selected fields only. Exclusive expiry and revoked choices refuse. Cap100 retained new receipts.

Saved-object validation
validateSavedGrant/readTestGrants enforce exact outer/ref keys, bounded allowlisted IDs/version, fixed purpose and contract, canonical24-character UTC times, exact duration interval, unique IDs and24 bound. grantStatus adds current timing checks. revokeTestGrant refuses an already future revokedAt rather than claiming success.
validateReturnPayload enforces exact selected nested summaries and mandatory contract/mode/purpose/mapping, supported statuses, bounded counts and nonaccredited/sample claims.
validateSavedReceipt/readTestReceipts enforce exact saved outer keys, fixed note/status, outer↔payload ID/date/partner/enrollment/contract agreement, canonical timestamps, unique IDs and100 bound. Retained grant matching checks grantId, partner, enrollment, content version/pathway, scopes and creation/expiry/withdrawal interval. New grant/test passes server now to reject future receipts. UI uses the reader before structured rendering/download. Saved malformed data is never silently upgraded.

Closure invariant
personalSizing serializes the ENTIRE personal state with JSON.stringify and measures its UTF-8 bytes. For every retained revokedAt===null, including expired choices, reserve22 bytes. A JSON null consumes4; a quoted canonical24-character UTC timestamp consumes26 and has no escaped characters. Withdrawal changes only that field, so actual bytes rise22 while reserve falls22. Worst retained reserve24*22=528. Effective bytes must remain<=1,000,000.
The API calls ensurePersonalSizing after every applyCommand result and before its durable update, including early-return learning-plan actions, profile/discussion growth, legacy preferences and reset. A sizing check only inside ecosystem cases is insufficient. Shared1.8MB closure capacity is unchanged. Receipt history is read diagnostically as receiptHistoryValid but its raw bytes are always measured; invalid receipt authority cannot prevent closure of a valid grant. The admitted-state invariant is not a claim that arbitrary corrupted storage is valid.

Client state and time

Server responses do not auto-rebase unsaved fields. Busy native fieldsets lock editing; canonical saved-choice comparison gates tests. Client clock refreshes periodically and when choices change; the server remains authoritative on every grant/test/withdraw. Existing root identity masking and context-change response safeguards remain applicable.
